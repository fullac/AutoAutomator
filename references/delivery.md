# 可靠交付

## 依赖与完整性

构建工具及回归测试需要 Python 3.9+，只用标准库；产物运行不需要 Python。先确认用户目标环境能调用 Python，否则按需求采用系统构建命令，不擅自安装运行时。只执行 Shell 示例不需要 Python。

```sh
python3 scripts/doctor.py --requires script
python3 scripts/doctor.py --requires app
python3 scripts/doctor.py --requires workflow
python3 scripts/verify_delivery.py '/path/to/delivery'
```

`doctor.py` 报告系统版本、工具缺失及构建依赖；不证明用户任务依赖或权限已满足。`verify_delivery.py` 检查 `build.json` 中的 SHA-256、包类型、服务声明及应用严格签名校验；不运行任务。旧构建记录没有 `schema_version: 1` 时需重新构建。摘要用于检测构建后的意外改动，不是可信发布者证明。

AppleScript 应用在资源装配完成后做 ad-hoc 签名，验证本机包完整性；未做 Developer ID 签名、公证或其他 Mac 验收。应用标识由名称稳定生成，也可用 `--bundle-id` 指定；代码及 ad-hoc 签名变化仍可能触发 TCC 重新授权。

## 失败与恢复

| 情况 | 行为与处理 |
| --- | --- |
| 交付目录已存在 | 构建拒绝覆盖；修改源码后向新目录重建 |
| 源码语法错误或系统工具缺失 | stderr 说明失败，返回非零状态；构建失败清理本次新目录 |
| 清单输出存在或是符号链接 | 拒绝覆盖；悬空符号链接不会被跟随创建目标 |
| 同时写同一清单 | 先写同目录临时文件，再以硬链接独占发布；失败不会替换他人的输出 |
| 输入目录无法读取 | 返回 77，不生成看似成功的空清单；检查实际宿主权限 |
| 换行文件名 | 行式清单提前拒绝；需要完整路径时使用 NUL 格式收据示例 |
| Shell 应用任务失败 | 系统错误窗口显示退出状态及日志位置；详情保留到 `~/Library/Logs/AutoAutomator/` |
| 工作流任务失败 | 检查 Automator 动作日志、错误提示或 CLI stderr，保留样例和退出状态 |
| macOS 文件访问等待授权 | 应用可能停在目录读取，日志尚无结果；由用户处理系统权限弹窗，不以终端成功代替应用授权 |

清单的原子发布需要输出目录所在文件系统支持硬链接；失败时会返回非零并清理临时文件，不自动降级为可覆盖写入。收据示例每次创建独立文件，适合并发路径记录，不代表业务任务已具有幂等或文件就绪保证。

## 安装和授权

Skill 安装目录只需 `SKILL.md`、`agents/`、`scripts/` 和 `references/`；开发用 `tests/`、`build/` 及 `.git/` 无需复制。也可以按 README 将仓库链接为 `autoautomator`。

快速操作与文件夹操作只在用户要求的范围内安装，按 [工作流说明](workflows.md) 操作。安装前检查目标是否存在，保存原绑定及启用状态，使用唯一测试名称。安装完成必须测试真实入口；卸载文件夹操作时先移除绑定，再移除自己安装的包，避免残留触发。不要删除用户已有服务或绑定。

`install.py` / `uninstall.py` 封装安装、缓存刷新、绑定和恢复。安装记录保留在 `~/Library/Application Support/AutoAutomator/installations/`，使用返回的 ID 卸载；已卸载记录保留供追溯。安装包后来被修改时拒绝删除，避免清掉用户改动。中断安装的已有文件与记录一致时可卸载恢复；清理失败会给出重试 ID。System Events 自动化权限属于运行安装器的宿主，工作流运行权限属于最终服务/后台宿主。

访问文稿、桌面、下载或其他受保护资源时，权限属于最终实际宿主。Shell 应用的授权主体是 `.app`，不是开发时的终端；文件夹操作检查后台宿主。只请求任务需要的权限，不默认要求完全磁盘访问，也不关闭系统保护。

## 交付记录

按实际任务记录：源文件和包位置、固定配置、输入输出、重建参数、执行入口、运行依赖、必要权限、目标 macOS、正常与失败样例结果。把“已构建”“完整性通过”“已通过真实入口”和“需要授权/尚未验证”分别写清楚。

若用户希望保留验收产物，可置于任务输出目录或仓库被忽略的 `build/`；可丢弃回归数据用系统临时目录。macOS 的 `/tmp` 指向 `/private/tmp`，系统清理后不能把这些临时文件视为交付证据的唯一副本。
